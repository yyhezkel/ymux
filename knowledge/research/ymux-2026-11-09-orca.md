Orca is [stablyai/orca](https://github.com/stablyai/orca), and the best ideas to take are usage-limit auto-continue, line-level diff review, and agent control verbs. It is MIT, so code and ideas are both reusable with the notice kept (`LICENSE`, Lovecast Inc.). Real code reuse is near zero because Orca is Electron/TS.

**Orca today** (`gh`, 2026-11-09):
- 119,966 stars, v1.4.255, near-daily releases, macOS/Windows/Linux, iOS/Android apps.
- It is not local-first any more. [SSH worktrees](https://www.onorca.dev/docs/ssh) install on the host and PTYs survive app close. There are also [`orca serve` and per-workspace VMs](https://www.onorca.dev/docs/ways-to-run).
- Not fully shipped: Orchestration, hibernation and Cloud VM are Experimental; Remote Servers are Beta.

**Other Orcas** (descriptions only, not researched): VirtusLab/orca (deterministic AI dev flows), echoVic/orca-agent (DeepSeek terminal agent), weill-labs/orca (full clones instead of worktrees). None is closer than stablyai.

## Ranked ideas

Paths under `docs/` are Orca's unless they start with `docs/vault/`. None of these was found rejected in ymux's `DECISIONS.md`.

1. **Usage-limit auto-continue, M.**
   - Orca: resumes a limit-cut chat at reset (`src/shared/agent-session/lifecycle/agent-session-usage-limit-continue.ts`). Chat UI only; I found no terminal variant.
   - ymux: `stop-failure` lights `failed` and nothing re-sends (`docs/vault/cli.md`).
   - Why: a fleet stalls overnight on one limit.
   - Fit: the daemon tracks state on the remote and sends into tmux, so it works with the desktop off, which beats Orca.
   - Risk: repeat failures need a cap (Orca added one at five, #40055). Log the error type only (Rule #1).

2. **Annotate diff, batch to agent, M.**
   - Orca: [line notes sent as one prompt](https://www.onorca.dev/docs/review/annotate-ai-diff), `src/renderer/src/components/diff-comments/`.
   - ymux: `app/src/DiffPane.tsx` has no comments.
   - Why: review from the desk without retyping file and line.
   - Fit: the diff already arrives over SSH; the batch goes through the pane write path.
   - Risk: anchors break on the pane's wholesale re-render.

3. **`ymux wait --for idle`, `ymux read`, `ymux worktree create`, S.**
   - Orca: [`terminal wait/read`](https://www.onorca.dev/docs/cli/reference).
   - ymux: `app/src-tauri/cli/src/main.rs` has `send` and `tree` only. `pane.scrollback` exists in RPC but has no verb. `COMPETITIVE-SCAN.md` 4.5 proposed the worktree verb; it never shipped.
   - Why: lets one Claude run others without sleep loops.
   - Fit: thin verbs over the existing tunnel and the traffic-light state; `workspace_create_project_worktree` already works on every transport.
   - Risk: idle detection depends on hooks.

4. **Repo-committed worktree recipe, S/M.**
   - Orca: [`orca.yaml`, `.worktreeinclude`](https://www.onorca.dev/docs/model/orca-yaml), which copies ignored files and runs setup and archive scripts.
   - ymux: per-workspace `setup_command` only; `worktrees.rs` copies nothing.
   - Why: a new worktree needs `.env` and dependencies before the agent starts.
   - Fit: run through `exec_script_over` on the remote.
   - Risk: a repo file runs commands on connect, so require a trust prompt.

5. **Scheduled prompts on the daemon, M.**
   - Orca: [cron, precheck, run history, per host](https://www.onorca.dev/docs/cli/automations), `src/main/automations/`.
   - ymux: none.
   - Why: nightly triage and sweeps.
   - Fit: `internal/term` already starts tmux sessions, and `handleResume` is the pattern. Precheck saves quota.
   - Risk: unattended permission gates and quota burn.

6. **Jump palette, S.**
   - Orca: [Cmd-J over worktrees and tabs, needs-you first](https://www.onorca.dev/docs/model/quick-open).
   - ymux: `CommandPalette.tsx` lists commands only (`App.tsx:1186`).
   - Why: faster than the sidebar at many sessions.
   - Fit: feed it `allPaneAgentRows()` with Queue ordering; no remote work.
   - Risk: low.

7. **PR status and "Fix broken checks", M.**
   - Orca: [PR tabs, failing checks handed to an agent](https://www.onorca.dev/docs/review/github).
   - ymux: no GitHub integration found.
   - Why: closes the loop after a push, which matches this repo's CI-only workflow.
   - Fit: run `gh` on the remote, so no token sits on the desktop.
   - Risk: `gh` missing or unauthenticated; polling limits.

8. **Hibernate idle agents, M.**
   - Orca: [stop after 30 idle minutes, resume on focus](https://www.onorca.dev/docs/agents/hibernation).
   - ymux: the reaper only flags `claude` (`docs/vault/server-go.md`). `session-meta` holds `claude_session_id`.
   - Why: frees RAM on crowded servers.
   - Fit: the daemon kills `claude` inside tmux and resumes in place.
   - Risk: kills background work an agent started. Measure RAM first.

9. **Transcript search in history, S.**
   - Orca: [search by title, cwd, branch, model, preview](https://www.onorca.dev/docs/agents/session-history); v1.4.255 extends it to SSH.
   - ymux: `history.go` pages with offset and limit only.
   - Fit: a daemon-side scan.
   - Risk: never log the query (Rule #1).

10. **Run/Task/Dispatch orchestration, L, last.**
    - Orca: [inbox, worker contract, decision gates](https://www.onorca.dev/docs/cli/orchestration), `src/main/runtime/orchestration/`.
    - ymux: none.
    - Fit: the daemon could own it, after #3.
    - Risk: still Experimental at Orca, and its commands have already been retired once. Try #3 plus a skill first.

## Does not fit

- **35+ agent adapters:** the user runs Claude.
- **Cloud VM recipes:** the user already owns the servers.
- **Computer Use, mobile emulator:** the work is on headless Linux.
- **Browser password vault:** Orca itself excludes paired-server and web clients.
- **Native mobile app:** PWA and Web Push cover it.
- **Linear, Jira, GitHub Projects, plugin catalog:** team and ecosystem features, not one operator's.

## Where ymux is ahead

- **Hebrew/RTL:** four RTL modules. Orca has no `he` locale in its 11 and no bidi file found.
- **Remote resume:** `handleResume` runs on the server, while [Orca's docs](https://www.onorca.dev/docs/agents/session-history) require a local workspace.
- **Structured status:** `[ymux-brief]` with Queue, against Orca's [free-text comment](https://www.onorca.dev/docs/cli/worktree-checkpoints).
- **Remote install:** committed static Go blobs, while Orca's terminals [may need build tools on the host](https://www.onorca.dev/docs/ways-to-run).
- **Remote server maturity:** Orca's is [Beta and documented for private networks only](https://www.onorca.dev/docs/remote-servers).
